# v2.4.2：数据不可用不再让工作流报错

本版对应要求：不一定需要本次新结果，但 workflow 应能正常完成。不是无条件忽略错误，也不把跳过当作真实数据验收成功。

| 情况 | workflow 结果 | 数据处理 |
|---|---|---|
| Yahoo 限流、下载不到行情 | 正常完成，摘要标记 skipped | 保留旧指针，不提交空结果 |
| 新鲜度或覆盖不足，发布门槛未通过 | 正常完成，摘要标记 skipped | 保留上一批 |
| 新数据满足发布要求 | 正常完成，标记 published | 校验后发布，执行 Git 提交 |
| 真实验收缺少行情/SRISK或数据过期 | 正常完成，标记 unavailable | 保存报告，跳过依赖新数据的前端构建 |
| 代码异常、JSON/CSV不一致、无效配置、测试/构建失败 | 失败 | 不隐藏真实软件错误 |

## 如何使用

将增量包按原路径覆盖到 v2.4.1 仓库根目录，包含 `.github`。本次增量不改变 data/current.json，不需要再次上传默认数据。

Daily workflow 改用 `python -m src.workflow_run`。Git 提交步骤仅当 `published=true` 时运行。行情不可用不会运行提交步骤。失败/跳过原因保留在 `data/last-attempt.json`，并写入 Actions Summary；artifact 保留诊断。

Live acceptance 工作流为原命令增加 `--allow-unavailable`，并且仅在 `ready=true` 时构建来自本次真实数据的前端。CLI 不传该选项时仍严格要求验收成功。

没有使用 `continue-on-error`、`|| true` 等将所有错误一律吞掉的方式。流水线只把明确的数据不可用、覆盖不足分类为操作性跳过；未分类的软件异常仍向外抛出。

## 验证

Python 162 项回归通过。新增验证覆盖：缺数据正常返回、旧数据保持不变、发布门槛拒绝正常返回、未知 TypeError 继续报错、仅成功发布允许提交。还通过独立进程检查了 Actions 输出字段、Daily 缺数据退出码 0、真实验收缺数据宽容模式退出码 0。

此前 v2.4.1 的前端代码和构建配置保持不变（仅版本号更新），已有 19 项前端测试及两种构建验证记录。当前 GitHub 连接只有读取权限，未替用户触发新版线上工作流。GitHub 平台故障、依赖下载故障和真实代码错误仍可能导致失败，不能承诺任何条件下永远绿灯。

工作流正常结束与取得新风险结果是两个状态。这里保证预期的数据不可用分支能正常结束，不声称 Yahoo 实时链路已经恢复。
